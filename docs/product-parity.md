# Product parity research: Hermes Agent and Grok Bot

Checked 2026-10-17 against first-party documentation and repositories. “Grokbot” is ambiguous: this document uses **Grok Bot**, the product documented at `x.ai`/`docs.x.ai` (SpaceXAI), not unrelated repositories or Telegram bots using the name. Where a behavior is only described in product documentation, the acceptance criterion tests the observable behavior rather than an implementation detail.

## Capability matrix

| Capability | Hermes Agent evidence | Grok Bot evidence | Crumble acceptance criteria |
| --- | --- | --- | --- |
| Named, independent agents | Bot Mode turns profiles into named Bots with role, model, memory, skills, avatar, credentials and chat history; profiles remain CLI-addressable. [`bot-mode`](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#bot-mode) | A Bot is a worker for a specific job with its own name/job/description and persistent cloud computer. [`overview`](https://docs.x.ai/grok-bot/overview), [`get started`](https://docs.x.ai/grok-bot/get-started) | Create, edit, duplicate, enable/disable, and delete agents. Each agent has a stable ID and isolated identity/configuration; deletion is explicit and recoverable only through documented backup/export. |
| Identity and persona | Advanced creation supports title, description, avatar, custom `SOUL.md`, model/provider pin and per-capability enablement. [`bot-mode`](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#creating-a-bot) | Settings are name, title/job and description; users can describe a workflow or record a demonstration. [`grok-bot-101`](https://x.ai/bot/guides/grok-bot-101#anatomy-of-a-bot) | Persist name, avatar, title, description, system instructions and behavioral preferences; edits apply to new turns without changing historical transcripts. |
| Persistent conversations | Every Bot has a canonical persistent Bot Chat; ordinary sessions remain available and can be resumed. [`bot-mode`](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#the-bots-pane) | Users message a named Bot; context, preferences and learned context persist across sessions. [`overview`](https://docs.x.ai/grok-bot/overview) | Stream replies, persist messages and tool events, resume after client/server restart, support multiple sessions per agent, and expose search/export of history. |
| Memory and context | Persistent memory and session search are built-in; memory is a documented feature and can be configured per profile. [`memory`](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory) | Context compounds; Bot memory, files, browser sessions and preferences persist, while conversations and learned context remain per Bot. [`overview`](https://docs.x.ai/grok-bot/overview) | Store durable memory separately from transcript, scope it per agent, show provenance/edit/delete controls, and prove that one agent cannot read another’s private memory without an explicit share. |
| Skills/workflows | Skills are procedural memory that Hermes can create/reuse; the skills system is first-class and can be enabled per Bot. [`skills`](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills) | A Bot can learn a workflow from a demonstration and save it as a reusable skill/routine. [`x.ai/bot`](https://x.ai/bot), [`grok-bot-101`](https://x.ai/bot/guides/grok-bot-101) | Install, enable/disable, version and run skills per agent; a demonstrated workflow can be saved, tested, and invoked by name with failure surfaced. |
| Tools, plugins and MCP | Hermes exposes built-in tools/toolsets and MCP server tools; capabilities can be filtered per profile. [`tools`](https://hermes-agent.nousresearch.com/docs/user-guide/features/tools), [`MCP`](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp) | Grok Bot supports connectors plus the same MCP servers, plugins and skills as Cursor; multiple accounts per service are supported. [`grok-bot-101`](https://x.ai/bot/guides/grok-bot-101#anatomy-of-a-bot) | Register MCP servers/connectors, expose a per-agent allowlist, persist auth references securely, and show tool-call input/output/errors in the execution trace. |
| Scheduling and triggers | Cron supports create/list/update/pause/resume/run/remove; Bot routines are namespaced cron jobs and appear beside the Bot chat. [`tools`](https://hermes-agent.nousresearch.com/docs/user-guide/features/tools), [`bot-mode`](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#routines) | Routines run on a schedule; Bots can also listen for events from other apps and trigger one another. [`grok-bot-101`](https://x.ai/bot/guides/grok-bot-101#using-grok-bot), [`x.ai/bot`](https://x.ai/bot) | Support one-shot, interval and cron schedules plus event/webhook triggers; pause/resume/run-now; record each run, outcome, retry and next-run time. |
| Background durability | Hermes documents durable Bot routines/group drivers and persistent profile state; gateway can continue work while Desktop is closed. [`bot-mode`](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#groups-and-group-chats) | Work runs on a persistent cloud computer and continues when laptop/app is closed. [`overview`](https://docs.x.ai/grok-bot/overview) | Jobs survive process/client restarts, have idempotent run IDs, resume or fail explicitly after interruption, and never silently duplicate side effects. |
| Multi-agent coordination | Bots can direct-message each other, use `@mentions`, and coordinate in 2–6 member group chats with per-member sessions. [`bot-mode`](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#groups-and-group-chats) | Bots run in parallel, message one another, share context in group chats and pass task ownership. [`overview`](https://docs.x.ai/grok-bot/overview) | Provide explicit handoff/message APIs, bounded fan-out/concurrency, shared-room transcript with attribution, and per-agent private context. A failed member must be visible and retryable. |
| Human approvals and isolation | Hermes documents command approval, authorization and container isolation. [`security`](https://hermes-agent.nousresearch.com/docs/user-guide/security) | Sensitive actions can pass through Auto Review; user takes over for passwords, 2FA and CAPTCHA. Enterprise controls include DLP/network policies. [`overview`](https://docs.x.ai/grok-bot/overview), [`get started`](https://docs.x.ai/grok-bot/get-started) | Gate risky tools/actions with once/session/always/deny decisions; support explicit capability boundaries, secret redaction, sandboxing, user takeover, cancellation and audit trail. |
| Models/providers | Hermes supports provider/model selection, including per-Bot model pinning and inherited defaults. [`bot-mode`](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#creating-a-bot), [`configuration`](https://hermes-agent.nousresearch.com/docs/user-guide/configuration) | Public docs describe Bots as product-level teammates but do not specify a per-Bot provider/model control surface. | Configure global providers/credentials plus per-agent model, fallback and inference parameters; validate credentials before first run and expose effective configuration. Treat Grok’s model routing as an unknown, not a parity requirement. |
| Observability and administration | Hermes Web Dashboard manages configuration, API keys, MCP, gateway, memory, credentials, sessions, logs, analytics, cron and skills; profile switcher makes write scope explicit. [`dashboard`](https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard) | Enterprise page promises access, network and audit controls; public docs do not expose a full run-log schema. [`enterprise`](https://x.ai/news/grok-bot-for-enterprise) | Show agent status, active runs, queue, tool calls, approvals, logs, errors, retries, token/cost usage and run history; make every mutating operation attributable and scoped. |
| Cross-platform interaction | Hermes gateway covers CLI, Desktop and 20+ messaging platforms; Bot Mode is in Desktop and CLI profiles remain compatible. [`documentation`](https://hermes-agent.nousresearch.com/docs), [`bot-mode`](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode) | Grok Bot is available on desktop and mobile; official docs describe shared cloud computers and mobile/desktop access. [`overview`](https://docs.x.ai/grok-bot/overview) | Define a versioned API consumed by macOS client and server; reconnect without losing stream/run state and keep agent identity consistent across clients. |

## Scope decisions for Crumble

1. Treat “agent” as a durable server-side entity, not a UI persona. A parity-complete implementation must exercise creation → configured tools/memory → conversation → scheduled/background run → observable result end to end.
2. Use Hermes as the reference for profile isolation, per-agent capability selection, cron lifecycle, persistent chats, and Bot-to-Bot messaging. Use Grok Bot as the reference for cloud-computer-style background work, workflow teaching, shared tools, routines/triggers, and human takeover.
3. Grok Bot is proprietary; public sources establish product behavior, not internal APIs or exact model/provider controls. Do not infer undocumented features (for example, per-Bot model selection, export format, or a particular scheduler syntax) from community sites.
4. Shared-computer semantics are a deliberate choice in Grok Bot: official docs say Bots share one persistent computer and isolation is per user, not per Bot. Crumble should default to stronger per-agent filesystem/credential isolation and require an explicit shared workspace grant for handoffs.
